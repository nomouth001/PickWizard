# 047. 자동선택(Quick Pick) 화면 — 스크롤 없이 한 화면에 다 보이게 하는 방법 보고

**문서 번호**: 047  
**작성일**: 2026-02-28  
**대상**: 럭키 찬스 645 — 자동선택(Quick Pick) 모달/화면  
**목적**: 스크롤 없이 포함할 번호·제외할 번호·확인 버튼이 한 화면에 모두 보이도록 변경하는 **방법** 정리. (본 문서는 코드 수정 없이 방법만 보고함.)

---

## 1. 현재 현상

- **화면 구성**: 상단 타이틀·자동선택(Quick Pick) 부제·X 버튼 → **포함할 번호** 그리드(1~45) → **제외할 번호** 그리드(1~45) → 하단 **확인** 버튼.
- **문제**: 모바일 뷰포트 높이 한계로 **제외할 번호** 그리드 하단(약 33~45번)과 **확인** 버튼이 잘려서, 스크롤해야만 모두 볼 수 있음.
- **원하는 결과**: 스크롤 없이 위 요소들이 모두 한 화면에 들어오도록 변경하는 방법을 정리.

---

## 2. 한 화면에 다 보이게 하는 방법 (개발 적용용)

아래는 추후 코드 수정 시 적용할 수 있는 방법들이다. 구현 난이도·UX 트레이드오프 순으로 정리했다.

### 2.1 그리드/요소 크기 축소 (권장 1순위)

| 항목 | 내용 |
|------|------|
| **숫자 칸 크기** | 1~45 그리드의 각 칸(버튼) 크기·패딩·간격을 줄여, 포함·제외 두 그리드가 차지하는 세로 높이를 감소시킨다. |
| **한 행 개수** | 현재 8개×6행(마지막 5개) 구조를 유지하되, 칸 크기만 줄이거나; 또는 **한 행에 9개**로 바꾸면 행 수가 줄어 세로 공간을 아낄 수 있다. (9×5 + 마지막 0개 → 5행 완결 등) |
| **폰트** | 그리드 내 숫자 폰트 크기를 한 단계 줄여 가독성을 유지하면서 높이를 절약한다. |

**효과**: 레이아웃 구조는 그대로 두고, 뷰포트에 맞게 콘텐츠 전체 높이만 줄여 스크롤을 없앨 수 있다.

---

### 2.2 섹션 접기(아코디언) 또는 탭 분리

| 방식 | 설명 |
|------|------|
| **접기** | "포함할 번호"는 기본 펼침, "제외할 번호"는 기본 **접힘**으로 두고, 탭 시에만 펼쳐서 그리드를 표시. 한 번에 하나의 그리드만 보이므로 세로 공간이 절반 가까이 줄어든다. |
| **탭** | "포함할 번호" / "제외할 번호"를 탭으로 나누어, 한 화면에는 하나의 그리드만 표시. 확인 버튼은 공통으로 두고, 탭 전환으로만 포함/제외를 편집. |

**효과**: 스크롤 없이 한 화면에 들어오지만, 포함/제외를 동시에 보며 조작하는 UX는 줄어든다.

---

### 2.3 뷰포트 기준 고정 배치 (미디어 쿼리·SafeArea)

| 항목 | 내용 |
|------|------|
| **전체 높이 100%** | 이 모달/화면의 루트를 `height: 100vh`(또는 플랫폼별 SafeArea 제외 높이)로 제한하고, 내부를 헤더 / 스크롤 영역 / 하단 버튼으로 나누지 **않고** 한 번에 배치. |
| **비례 축소** | 포함·제외 그리드를 `flex` 또는 비율로 배치하고, 사용 가능 높이에 맞춰 그리드 칸 크기·행 간격을 **자동으로** 줄이도록 계산(미디어 쿼리 또는 레이아웃 위젯으로). |

**효과**: 기기별로 “한 화면 높이”에 맞춰 요소 크기가 조정되므로, 스크롤 없이 다 보이게 할 수 있다.

---

### 2.4 제외할 번호만 그리드 대신 입력 방식

- "제외할 번호"만 1~45 그리드 대신 **텍스트 입력 + 칩/태그**(예: "13, 14, 15" 입력 후 태그로 표시) 방식으로 바꾼다.
- "포함할 번호"는 그리드 유지(최대 6개라 공간이 적음).

**효과**: 제외 그리드가 사라져 세로 공간이 크게 줄어들어, 확인 버튼까지 한 화면에 넣기 쉬워진다. (045 문서의 B안에 해당.)

---

### 2.5 상단 헤더·여백 축소

- "럭키 찬스 645"·"자동선택 (Quick Pick)"·X 버튼 영역의 패딩·폰트 크기를 줄인다.
- "포함할 번호" / "제외할 번호" 라벨 행의 위아래 마진을 줄인다.

**효과**: 그리드와 버튼 크기를 바꾸지 않아도, 상단에서 확보한 세로 공간만으로 하단이 화면에 들어올 수 있다.

---

## 3. 방법 우선순위 제안

| 순위 | 방법 | 스크롤 제거 | UX 유지 | 구현 부담 |
|------|------|-------------|---------|-----------|
| 1 | 그리드/요소 크기 축소 + 상단 여백 축소 | ◎ | ◎ (동시에 두 그리드 모두 표시) | 낮음 |
| 2 | 뷰포트 기준 비례 배치 | ◎ | ◎ | 중간 |
| 3 | 제외할 번호만 입력+칩 방식 | ◎ | △ (제외는 그리드 아님) | 중간 |
| 4 | 섹션 접기(아코디언) 또는 탭 분리 | ◎ | △ (한 번에 하나만 표시) | 중간 |

- **우선 적용 권장**: **2.1(그리드·요소 축소) + 2.5(상단·여백 축소)**. 구조 변경 없이 높이만 줄여 대부분 기기에서 스크롤 없이 한 화면에 넣을 수 있다.
- 그래도 부족한 소형 기기는 **2.2(제외할 번호 접기)** 또는 **2.3(뷰포트 비례)**를 추가로 적용하면 된다.

---

## 4. 코드 수정 없이 사용자가 할 수 있는 것 (참고)

- **화면 세로 회전**: 기기를 가로로 돌리면 뷰포트 높이가 줄어들어 스크롤이 더 필요할 수 있어, 이 화면만은 **세로**로 보는 편이 유리할 수 있음.
- **기기 설정**: 시스템 폰트 크기를 "기본" 또는 "작게"로 두면, 앱이 시스템 폰트를 쓰는 경우 일부 여백·텍스트가 줄어들 수 있음. (동작 여부는 앱 구현에 따름.)
- **큰 화면**: 태블릿이나 큰 폰에서는 이미 한 화면에 다 들어올 수 있음.

위는 앱 코드를 바꾸지 않고 사용자 환경으로 완화할 수 있는 보조 수단이다.
