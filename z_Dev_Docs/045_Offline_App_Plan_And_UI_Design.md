## 2. 기능 요구사항

### 2.1 알고리즘

| ID | 이름 | 설명 | 포함/제외 |
|----|------|------|-----------|
| 1 | 자동선택 (Quick Pick) | 1~45 중 6개 완전 무작위. 포함 번호는 고정, 나머지 칸만 랜덤. 제외 번호는 후보에서 제거. | ✅ 지원 |
| 9 | 만 번 뽑기 6개 | 1~45를 10,000회 랜덤 추출 후 출현 빈도 상위 6개. 포함/제외는 풀(pool)에서 반영. | ✅ 지원 |

### 2.2 포함/제외 번호 규칙 (백엔드 상수와 동일)

| 항목 | 규칙 | 비고 |
|------|------|------|
| **포함할 번호** | 1~45, 최대 **6개**, 중복 불가 | 포함 개수만큼 랜덤 칸 수 감소 (6개면 1세트 고정) |
| **제외할 번호** | 1~45, 최대 **39개**, 중복 불가 | 추첨 후보 풀에서 제거 |
| **겹침** | 포함 번호와 제외 번호는 서로 겹치면 안 됨 | UI/검증에서 차단 |

### 2.3 생성 개수

- 5개 / 10개 퀵 버튼 + **직접 입력**(1~100개) — 현재와 동일하게 유지.

### 2.4 기타 기능

- 생성 결과 화면: 세트별 번호 카드, 저장(내 번호) — 유지.
- 홈: 최신 회차는 **오프라인 앱에서는 제거 또는 “로컬 저장분만 표시”** 등 정책에 따라 결정. 본 문서에서는 “최신 회차 카드 비표시 또는 간단 안내 문구”로 두고, 구현 시 선택.
- 설정: 언어 변경, (선택) 테마 등 — 다국어 유지.

## 3. 화면별 UI 디자인

### 3.1 전체 흐름·화면 구성

- **토탈 2화면** (또는 런칭 화면까지 만들면 **3화면**).
  1. **화면 1**: 홈 + 번호 생성 (알고리즘 선택, 포함/제외, 생성 개수, 번호 생성 버튼). 여기서 “번호 생성” 탭 시 **새 화면**으로 이동.
  2. **화면 2**: **결과 화면** — 생성된 번호만 보여 주는 **별도 화면**. 알고리즘명, N개 세트, 세트별 번호 카드, “내 번호로 저장” + (아래 §4) 헤더 배너·생성된 번호세트 아래 배너 여러 겹.
  3. **(선택) 화면 3**: 런칭(스플래시) 화면.

```
[홈/번호생성] —(번호 생성 탭)—→ [결과 화면] (새 화면)
       ↑
[설정] (언어 등)
```

### 3.2 홈 화면 (Home)

- **구성**: 현재와 유사. 상단 AppBar(타이틀, 설정 아이콘), 하단에 **번호 생성하기** 진입 카드/버튼.
- **변경점**:
  - 오프라인 전용이면 “최신 회차” 카드는 제거하거나, “오프라인 모드 — 당첨 확인은 동행복권에서” 같은 안내만 표시 가능.
  - 코인/지갑 비활성(043)이면 코인 영역 계속 미노출.
- **다국어**: `context.l10n.homeTitle`, `generateNumbers` 등 기존 키 사용.

### 3.3 번호 생성 화면 (Generate)

- **레이아웃**: 현재처럼 **카드 한 장** 안에 “알고리즘 선택” + **선택 시 확장 영역**.
- **도움말(?) 패턴 유지**: 현재 모바일 앱과 동일하게, **? (물음표/도움말) 아이콘**을 탭하면 해당 항목에 대한 설명을 모달 또는 툴팁으로 표시한다. 알고리즘별 도움말·파라미터(포함/제외, 생성 개수 등)별 도움말을 모두 이 방식으로 제공한다.

#### 상단: 알고리즘 선택

- **라디오 리스트 2개만** 표시:
  1. **자동선택 (Quick Pick)** — 부제: 1~45 중 6개 무작위. **?** 탭 시 상세 설명.
  2. **만 번 뽑기 6개** — 부제: 10,000회 랜덤 추출 후 빈도 상위 6개. **?** 탭 시 상세 설명.
- 각 행에 알고리즘 이름 + 짧은 설명 + **도움말 버튼(?)**.  
- **비용/코인 문구**: 오프라인·광고 전용이면 “무료”만 표시하거나 생략.

#### 확장 영역 (선택한 알고리즘에 공통)

아래 순서로 배치:

1. **포함할 번호 (Include)**
   - 라벨: “포함할 번호” + **?** (탭 시 설명). 다국어 키 예: `includeNumbers`.
   - 안내: “반드시 뽑히게 할 번호 (최대 6개)”.
   - **UI 패턴 (안)**  
     - **A안**: 1~45 그리드(칸 탭으로 선택/해제), 선택된 번호만 모아서 칩/태그로 표시.  
     - **B안**: 텍스트 필드 + “추가” (한 번호씩 또는 쉼표 구분 입력), 선택된 번호 리스트 + 개별 삭제.
   - **권장**: A안(그리드)이 로또 앱에서 익숙하고, 1~45 시각화에 유리. B안은 구현이 단순.
   - 표시: “현재 N개 선택 (최대 6개)” / 6개 초과 시 “6개까지만 선택 가능” 등.

2. **제외할 번호 (Exclude)**
   - 라벨: “제외할 번호” + **?** (탭 시 설명).
   - 안내: “뽑지 않을 번호 (최대 39개)”.
   - UI: 포함과 동일한 패턴(그리드 또는 입력+리스트).  
   - 검증: 포함 번호와 겹치면 “포함한 번호는 제외할 수 없습니다” 등 메시지.

3. **생성 개수**
   - 기존과 동일: “생성 개수” 제목 + **?** (탭 시 설명) + **5개 / 10개 / 직접 입력** 버튼 + (직접 입력 시) 숫자 필드 1~100.

4. **번호 생성 버튼**
   - 풀폭 버튼: “번호 생성” (아이콘 + 텍스트).  
   - 비활성: 알고리즘 미선택, 또는 포함+제외 조건 오류(예: 남는 풀 크기 &lt; 6)일 때 비활성 + 툴팁/스낵으로 사유 안내.

### 3.4 결과 화면 (Result) — 생성 번호 전용 새 화면

- **역할**: “번호 생성” 버튼 탭 후 **새 화면**으로 이동하여, 생성된 번호만 보여 준다. (번호 생성 폼과 같은 화면이 아님.)
- **구성**: 알고리즘 이름, “N개 세트 생성”, 세트별 `NumberCard`, “내 번호로 저장” 버튼. 그 아래에 광고 배치(§4): 헤더 배너 + **생성된 번호세트들 아래** 배너 여러 겹.
- **다국어**: `generationResult`, `setsGenerated`, `saveAsMyNumbers` 등 기존 키 사용.

### 3.5 설정 화면 (Settings)

- **유지**: 언어 선택(한국어, English 등) — 다국어 유지.
- 기타 설정 항목은 기존 구조 유지.

## 4. 광고 배치

- **수익 모델**: 043·041에 따라 광고 전용. 배너·전면·보상형 등 정책은 041 참조.
- **배치 원칙**: **결과 화면**(생성된 번호를 보여 주는 새 화면)에서 **헤더**와 **생성된 번호세트들 아래**에 배너를 **여러 겹** 쌓아 한 화면을 채운다. (번호 생성 폼이 있는 화면이 아니라, 생성 후 이동하는 결과 전용 화면.)

### 4.1 공통: 헤더·푸터

| 구역 | 설명 |
|------|------|
| **헤더** | AppBar 아래 또는 콘텐츠 최상단에 배너 1줄. (필요 시 고정 배너 영역) |
| **푸터** | 화면 하단 고정 또는 스크롤 끝에 배너 1줄. |

- 필요 시 홈·번호 생성·설정 등에도 헤더·푸터 배너 적용 가능. **결과 화면**은 §4.2대로 반드시 적용.

### 4.2 결과 화면 전용 (생성 번호 새 화면)

- **헤더**: 결과 화면 콘텐츠 최상단(알고리즘명·N개 세트 정보 위)에 배너 영역.
- **생성된 번호세트 아래**: 세트별 `NumberCard` + “내 번호로 저장” 버튼 **아래**부터 화면 끝까지, **배너를 여러 겹(2~3단 이상)** 쌓아 한 화면을 채운다.  
  - 스크롤 시: [헤더 배너] → [알고리즘명, N개 세트] → [번호 카드 1][2]…[N] → [내 번호로 저장] → [배너 1][배너 2][배너 3]… → [푸터 배너].

### 4.3 결과 화면 와이어프레임 (광고 영역 포함)

```
┌─────────────────────────────────────────┐
│ [헤더 배너]                               │  ← 4.1
├─────────────────────────────────────────┤
│ 자동선택 (Quick Pick)  ·  5개 세트 생성   │
├─────────────────────────────────────────┤
│ ①  [3][7][21][28][35][42]                │
│ ②  [1][12][19][26][33][40]              │
│ ③  ...                                   │  ← 생성된 번호세트들
│ ④  ...                                   │
│ ⑤  ...                                   │
├─────────────────────────────────────────┤
│ [    내 번호로 저장    ]                  │
├─────────────────────────────────────────┤
│ [배너 1]                                  │  ← 4.2 생성된 번호세트 아래
│ [배너 2]                                  │     여러 겹으로 화면 채움
│ [배너 3]                                  │
│ ...                                      │
├─────────────────────────────────────────┤
│ [푸터 배너]                                │  ← 4.1
└─────────────────────────────────────────┘
```

- 구현 시: 배너 위젯을 2~3개 이상 세로로 나열하고, 필요하면 플레이스홀더 높이를 주어 빈 공간 없이 한 화면이 채워지도록 한다. 041의 배너 정책(노출 간격·개수 제한 등)을 따른다.

## 5. 다국어 유지

- **로컬라이제이션**: 기존 `app_localizations`, `app_ko.arb`, `app_en.arb` 등 구조 유지.
- **추가 키 제안** (포함/제외 관련):
  - `includeNumbers` — “포함할 번호” (기존 `AppStrings.includeNumbers` 또는 l10n 키)
  - `excludeNumbers` — “제외할 번호”
  - `includeNumbersHint` — “반드시 뽑히게 할 번호 (최대 6개)”
  - `excludeNumbersHint` — “뽑지 않을 번호 (최대 39개)”
  - `includeExcludeOverlapError` — “포함한 번호는 제외할 수 없습니다”
  - `tooFewPoolError` — “제외/포함 조건으로 선택 가능한 번호가 6개 미만입니다”
- **알고리즘 이름/설명**: 자동선택·만 번 뽑기 6개 두 개만 사용. `algorithm1Name`/`algorithm1Desc`, 알고리즘 9용은 `algorithm9Name` = “만 번 뽑기 6개”, `algorithm9Desc` 등 전용 키 추가. **?** 도움말 내용도 이 키들 또는 별도 help 키로 다국어 제공.

## 6. 데이터·로직 요약

### 6.1 앱 내 상태

- `selectedAlgorithmProvider`: 1 또는 9 (AlgorithmInfo 또는 id만 저장).
- `includeNumbersProvider`: `List<int>` (최대 6개).
- `excludeNumbersProvider`: `List<int>` (최대 39개).
- `numberOfSetsProvider`: 1~100 (기본 5).

### 6.2 번호 생성 (오프라인)

- **자동선택**: 1~45에서 exclude 제거, include는 고정 포함 후 나머지 칸만 랜덤 채움. (백엔드 `algorithm_01_random` 로직과 동일.)
- **만 번 뽑기 6개**: 1~45에서 exclude 제거, include는 후보 풀에서 제외한 뒤, 풀에서 10,000회 랜덤 추출 → 빈도 상위 (6 - include개수) 만큼 선택 후 include와 합쳐 정렬. (백엔드 `algorithm_09_monte_carlo_top6` 로직과 동일.)
- 검증: `include ∩ exclude == ∅`, 그리고 “남는 풀 크기 ≥ (6 - include 개수)” 이어야 생성 가능.

### 6.3 결과 저장

- 기존처럼 `GeneratedNumbers` 모델로 로컬 저장, “내 번호” 화면에서 조회. (알고리즘 ID 1/9만 사용.)

## 7. 구현 시 유의사항

- **알고리즘 목록**: API 대신 앱 내 상수 2개(1, 9)만 사용. `algorithmsProvider`를 오프라인용 고정 리스트로 교체하거나, API 실패 시 이 2개만 보이도록 fallback.
- **GenerateRequest**: 오프라인 시 `GenerateRequest` 대신 로컬 함수에 `algorithmId`, `nSets`, `includeNumbers`, `excludeNumbers` 전달.
- **포함/제외 UI**: 그리드(1~45) 시 45개 칸 터치로 선택/해제, 포함 6개·제외 39개·겹침 검증을 실시간으로 적용.
- **다국어**: 모든 새 라벨·메시지는 arb에 추가해 다국어 유지.
- **도움말(?) 패턴**: 현재 앱의 알고리즘 도움말 버튼·파라미터 도움말 버튼과 동일하게, **?** 아이콘 탭 시 설명 모달을 띄우는 방식을 유지한다. (예: `_buildAlgorithmHelpButton`, `_buildParameterHelpButton` 등.)
- **광고 배치**: §4에 따라 **결과 화면**(생성 번호 전용 새 화면)에서 헤더 배너 + 생성된 번호세트들 아래 배너를 여러 겹 쌓아 한 화면을 채운다. 041 정책 준수.
