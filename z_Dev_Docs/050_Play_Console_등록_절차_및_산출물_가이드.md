# 050. Google Play Console 등록 절차 및 단계별 작업/산출물 가이드

본 문서는 Android 앱을 Google Play Console에 등록/출시할 때 필요한 절차를 **실행 순서 기준**으로 정리한 가이드이다.  
각 단계마다 `무엇을 해야 하는지`, `무엇을 제출해야 하는지(산출물)`, `완료 기준`을 함께 제공한다.

---

## 0. 범위 및 전제

- 대상: 신규 앱을 Play Console에 처음 등록하여 `내부 테스트` 또는 `프로덕션`까지 진행하는 경우
- 기준 앱: Flutter 기반 Android 앱 (`AAB` 업로드 방식)
- 권장: 먼저 `내부 테스트(Internal testing)`로 검증 후 프로덕션 전환
- 브랜드·스토어 표기명: **PickWizard** (언어별 권장 제목은 `050-1_Play_Store_설명.md` 표 참고)
- Dart 패키지명·`applicationId`/번들 ID·폴더 구조까지 통일할 때: `050-4_PickWizard_패키지_ID_전환_계획_및_체크리스트.md`

---

## 1. 사전 준비 (계정/앱 기본 정보)

### 1.1 해야 할 작업

1. Google Play Console 개발자 계정 준비
2. 앱 이름/기본 언어/패키지명(`applicationId`) 확정
3. 앱 서명 전략 결정  
   - 권장: **Play App Signing 사용**
4. 개인정보처리방침 URL 준비

### 1.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 계정 | Play Console 접근 가능한 개발자 계정 | Owner/Admin 권한 |
| 앱 식별 | 앱 이름, 패키지명, 기본 언어 문서 | 예: `com.pickwizard.app` (실제 `applicationId`와 일치) |
| 정책 | 개인정보처리방침 URL | 공개 접근 가능한 HTTPS URL |
| 서명 | 업로드 키(keystore) 및 보관 정책 | `.jks/.keystore`, 비밀번호 관리 문서 |

### 1.3 완료 기준

- Play Console에서 앱 생성 가능 상태
- 패키지명/앱명/언어가 내부 문서와 일치
- 개인정보처리방침 URL이 외부에서 열림

---

## 2. 앱 생성 및 Play Console 기본 설정

### 2.1 해야 할 작업

1. Play Console에서 새 앱 생성
2. 앱 카테고리/유형(앱) 선택
3. 개발자 프로그램 정책, 앱 배포 관련 초기 확인 항목 체크

### 2.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 콘솔 설정 | Play Console 앱 생성 완료 상태 | 앱 대시보드 진입 가능 |
| 기본 메타 | 앱 이름, 기본 언어, 카테고리 | 콘솔 입력 완료 |
| 정책 확인 | 초기 정책 확인 완료 기록 | 체크리스트 또는 스크린샷 |

### 2.3 완료 기준

- 앱 대시보드에서 `출시 대시보드` 접근 가능
- 기본 설정 누락 경고 없이 다음 단계 이동 가능

---

## 3. 앱 빌드 준비 (릴리스 AAB 생성)

### 3.1 해야 할 작업

1. 버전 정보 갱신 (`versionName`, `versionCode`)
2. 릴리스 빌드 생성 (`.aab`)
3. 서명 설정 확인 (업로드 키/Play App Signing)
4. 디버그 설정, 테스트 키, 개발용 코드 제거 여부 점검

### 3.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 빌드 산출물 | Android App Bundle | `app-release.aab` |
| 버전 기록 | 버전 관리 로그 | 예: `1.0.0+1` |
| 서명 정보 | 키스토어 경로/별칭/관리 문서 | 보안 저장소 또는 내부 문서 |
| 품질 확인 | 로컬 설치/기능 점검 결과 | 테스트 체크리스트 |

### 3.3 완료 기준

- 업로드 가능한 `AAB` 파일 확보
- 버전 코드 중복 없음
- 릴리스 빌드에서 치명 오류 없음

---

## 4. 스토어 등록정보(Store Listing) 작성

### 4.1 해야 할 작업

1. 앱 설명 문구 작성  
   - 짧은 설명(최대 80자)  
   - 전체 설명(최대 4000자)
2. 그래픽 에셋 업로드  
   - 앱 아이콘 512x512  
   - Feature Graphic 1024x500  
   - 휴대전화 스크린샷(최소 2장, 권장 4~8장)
3. 연락처 정보 입력 (이메일 필수)
4. 개인정보처리방침 URL 입력

### 4.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 텍스트 | 짧은 설명/전체 설명 원고 | 다국어 운영 시 언어별 원고 |
| 이미지 | 앱 아이콘 | 512x512 PNG (알파 없음 권장) |
| 이미지 | Feature Graphic | 1024x500 PNG/JPG |
| 이미지 | 스크린샷 | 기기 비율 일관성 유지 |
| 연락처 | 개발자 이메일/웹사이트/전화(선택) | 콘솔 입력 완료 |
| 정책 | 개인정보처리방침 URL | HTTPS, 공개 접근 가능 |

### 4.3 완료 기준

- 스토어 등록정보 항목이 모두 저장됨
- 해상도/비율 오류 없이 이미지 업로드 완료

---

## 5. 앱 콘텐츠(App Content) 및 정책 설문

### 5.1 해야 할 작업

1. 데이터 보안(Data safety) 설문 작성  
   - 수집 데이터 종류, 처리 목적, 암호화/삭제 요청 등
2. 콘텐츠 등급(Content rating) 설문 완료
3. 광고 포함 여부 선언
4. 타깃 연령/아동 대상 여부(필요 시) 설정
5. 정부/금융/헬스 등 특수 카테고리 해당 시 추가 문서 제출

### 5.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 정책 문서 | 데이터 흐름 정리표 | 수집 항목, 저장 위치, 보존 기간 |
| 설문 결과 | Data safety 입력 완료 | 콘솔 상태 완료 |
| 설문 결과 | 콘텐츠 등급 결과 | 등급 결과 화면 |
| 선언 정보 | 광고 여부/연령 타깃 설정 | 콘솔 입력 완료 |

### 5.3 완료 기준

- 앱 콘텐츠 섹션의 필수 질문이 모두 `완료` 상태
- 정책 위반 경고 없이 출시 가능 상태

---

## 6. 등록 이후 1단계: 테스트 트랙 배포 (내부 테스트)

### 6.1 해야 할 작업

1. `내부 테스트` 트랙 생성
2. 릴리스 노트 작성 후 AAB 업로드
3. 테스터 그룹(이메일 또는 Google Group) 등록
4. 테스트 링크 배포 후 설치/실행 검증

### 6.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 배포물 | 내부 테스트 릴리스 | AAB + 릴리스 노트 |
| 테스터 관리 | 테스터 목록 | 이메일 목록/그룹 링크 |
| 검증 결과 | 설치/결제/광고/권한 테스트 결과 | QA 체크리스트 |
| 이슈 기록 | 발견 버그 및 조치 내역 | 이슈 트래커 |

### 6.3 완료 기준

- 테스터가 실제 단말에서 설치 가능
- 핵심 시나리오(앱 실행, 주요 기능, 종료/재실행) 통과

---

## 7. 등록 이후 2단계: 클로즈드/오픈 테스트 확장 (선택)

### 7.1 해야 할 작업

1. 내부 테스트 이슈 수정 후 새 버전 AAB 재업로드
2. 필요 시 `클로즈드 테스트` 또는 `오픈 테스트` 트랙 생성
3. 테스트 대상/국가/참여 방식 설정
4. 테스트 피드백 수집 및 치명 이슈 정리

### 7.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 테스트 배포물 | 클로즈드/오픈 테스트 릴리스 | AAB + 릴리스 노트 |
| 참여자 정보 | 테스터 확장 목록 | 메일 리스트/공개 참여 링크 |
| 피드백 기록 | 버그/개선 요청 목록 | 우선순위 포함 이슈 리스트 |
| 안정화 결과 | 재검증 리포트 | 수정 완료 항목/잔여 리스크 |

### 7.3 완료 기준

- 테스트 범위 확대 후 치명 결함(크래시, 데이터 손실, 결제 오류) 없음
- 프로덕션 전환 가능한 안정화 버전 확정

---

## 8. 등록 이후 3단계: 프로덕션 제출 전 최종 점검

### 11.1 해야 할 작업

1. 프로덕션 트랙 릴리스 초안 생성
2. 국가/지역(배포 국가) 확정
3. 가격 정책(무료/유료) 및 인앱상품 상태 점검(사용 시)
4. `앱 콘텐츠`, `스토어 등록정보`, `정책` 경고 항목 재확인
5. 최종 빌드 무결성 점검(버전코드, 서명, 권한, 네트워크)

### 8.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 출시 설정 | 프로덕션 릴리스 초안 | 릴리스 노트 포함 |
| 배포 설정 | 국가/지역 목록 | 타깃 마켓 최종판 |
| 정책 확인 | 사전 경고/차단 항목 점검표 | 누락 0건 상태 |
| 기술 점검 | 최종 빌드 검증 결과 | QA 시트/테스트 리포트 |

### 8.3 완료 기준

- 프로덕션 제출 전 필수 항목 경고가 모두 해소됨
- 출시 심사 제출 버튼 실행 가능한 상태

---

## 9. 등록 이후 4단계: 프로덕션 심사 제출 및 검토 대응

### 9.1 해야 할 작업

1. `출시 검토로 전송`으로 프로덕션 심사 제출
2. 검토 상태(검토 중/거부/승인) 모니터링
3. 거부 시 사유 분석 후 수정 버전 재제출
4. 승인 후 실제 게시 시간/국가별 반영 상태 확인

### 9.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 제출 이력 | 제출 일시/버전 로그 | 릴리스 관리 문서 |
| 검토 결과 | 승인/거부 사유 기록 | Console 알림 캡처/요약 |
| 재제출 자료 | 수정 내역 및 재검증 결과 | 변경 로그 + QA 결과 |

### 9.3 완료 기준

- 앱 상태가 `게시됨(Published)` 또는 게시 예약 완료 상태
- 주요 타깃 국가에서 스토어 노출 확인

---

## 10. 등록 이후 5단계: 배포(롤아웃) 실행 및 완료 판정

### 10.1 해야 할 작업

1. 단계적 롤아웃(권장) 설정  
   - 예: 5% -> 20% -> 50% -> 100%
2. 각 롤아웃 구간에서 크래시/ANR/리뷰 급증 여부 모니터링
3. 이상 징후 발생 시 롤아웃 중지(또는 보류) 후 핫픽스 릴리스 준비
4. 문제 없으면 100% 배포 완료 처리

### 10.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 롤아웃 계획 | 퍼센트별 배포 일정표 | 날짜/시간/판정 기준 포함 |
| 운영 지표 | 크래시율/ANR/오류로그 | 구간별 비교 리포트 |
| 대응 기록 | 롤백/중지/재개 이력 | 운영 로그 |
| 완료 보고 | 배포 완료 보고서 | 최종 배포율 100% 확인 |

### 10.3 완료 기준

- 목표 국가/사용자 대상 100% 배포 완료
- 배포 후 안정성 지표가 내부 기준치 이내

---

## 11. 출시 후 운영 (Post-Launch)

### 8.1 해야 할 작업

1. ANR/Crash 모니터링 (Android vitals, Firebase Crashlytics 등)
2. 사용자 리뷰 및 평점 대응
3. 긴급 수정 필요 시 핫픽스 릴리스 배포
4. 정기 업데이트 주기 운영

### 11.2 필요한 산출물

| 구분 | 산출물 | 형식/예시 |
|------|--------|-----------|
| 운영 지표 | 크래시율/ANR 리포트 | 주간/월간 리포트 |
| CS 대응 | 리뷰 답변 가이드 | 템플릿 문서 |
| 업데이트 기록 | 릴리스 이력 | 버전별 변경사항 |

### 11.3 완료 기준

- 출시 후 안정성 지표 모니터링 체계 확보
- 업데이트/이슈 대응 프로세스 문서화 완료

---

## 13. 실무 권장 순서 (요약)

7. 필요 시 클로즈드/오픈 테스트 확장
8. 프로덕션 제출 전 최종 점검
9. 프로덕션 심사 제출 및 검토 대응
