## 1. 요건 정리


| 요건        | 설명                                        |
| --------- | ----------------------------------------- |
| **동작 환경** | 앱이 **서버에 연결 없이** 모바일 기기 위에서만 동작 (완전 오프라인) |
| **수익**    | **광고**로 앱 수익 확보 (043 수익모델: 광고 전용)         |

## 3. 오프라인 가능 여부 분류

### 3.1 서버/네트워크/대용량 리소스 없이 동작 가능

- **ID 1 — 자동선택 (Quick Pick)**  
  - `historical_data` 미사용. 1~45 중 6개 무작위 선택만 수행.  
  - **오프라인**: ✅ 완전 가능 (Dart로 이식 용이).
- **ID 9 — 몬테카를로 상위 6개**  
  - `historical_data` 미사용. 1~45를 10,000회 랜덤 추출 후 출현 빈도 상위 6개를 1세트로 사용.  
  - **오프라인**: ✅ 완전 가능 (로직 단순, Dart 이식 용이).

### 3.2 과거 당첨 데이터 필요 (데이터만 있으면 오프라인 가능)

- **ID 2, 4, 5, 6, 7**  
  - 모두 `historical_data`(과거 당첨 번호 DataFrame)를 사용.  
  - 데이터가 없을 때는 백엔드에서 랜덤 fallback.  
  - **오프라인**: ⚠️ 앱에 **당첨 데이터를 에셋으로 번들링**하고, 동일 로직을 Dart로 구현하면 오프라인 가능. (구현량·앱 용량 증가)

### 3.3 서버 또는 외부 API 필수 (오프라인 앱에 부적합)

- **ID 3 — LSTM**  
  - PyTorch 모델, 학습/추론 파이프라인, 상대적으로 큰 리소스.  
  - 모바일 온디바이스 추론으로 이식 가능은 하나, 래핑 앱의 범위에서는 부담이 큼. **제외 권장.**
- **ID 8 — AI Selection**  
  - Google Gemini API 호출 필수.  
  - **오프라인**: ❌ 불가. **제외.**

## 4. 앱 래핑 추천: 선정 알고리즘

요건(서버 없이 모바일에서만 동작 + 광고 수익)을 만족하려면 **의존성이 전혀 없는 알고리즘**만 앱에 넣는 것이 가장 안전하고 구현 부담이 적다.

### 4.1 1차 추천: 최소 구성 (2종)


| ID    | 알고리즘              | 선정 이유                                                    |
| ----- | ----------------- | -------------------------------------------------------- |
| **1** | 자동선택 (Quick Pick) | 서버·데이터 불필요, 사용자에게 익숙한 “자동” 옵션, 구현 난이도 최하                 |
| **9** | 몬테카를로 상위 6개       | 서버·데이터 불필요, “랜덤 시뮬레이션 기반”이라는 차별화 포인트, 로직이 단순해 Dart 이식 용이 |


- **구현 방식**: 위 두 알고리즘의 로직을 **Dart로 앱 내에 직접 구현**.  
- **데이터/API**: 당첨 이력 조회·회차 정보·번호 생성 모두 **서버 호출 없이** 앱 내에서만 처리.  
- 번호 생성 결과는 기존과 같이 로컬 저장(예: Hive)만 하면 됨.

이렇게 하면 **서버 완전 미연동** 상태로 앱만으로 출시 가능하고, 043·041에 따른 **광고 전용 수익** 구조와도 정합적이다.

### 4.2 2차 확장 (선택): 번들 데이터 + 빈도/핫콜드

- 앱에 **최근 N회차 당첨 번호**를 JSON/CSV 등으로 에셋 번들링.  
- **ID 6 (출현 번호 빈도 기반)** 또는 **ID 7 (핫/콜드 넘버)** 중 1~2개를 Dart로 구현해 “통계 기반” 옵션을 추가할 수 있음.  
- 이 경우에도 **서버 연결은 필요 없음**. 단, 앱 용량 증가·에셋 갱신 주기(주기적 앱 업데이트 또는 에셋만 갱신하는 정책) 검토가 필요.

## 5. 수익 모델: 광고 전용

- 043 수익모델(광고 전용, 코인/지갑 비활성)을 그대로 적용하면 됨.  
- **배너·전면·보상형** 광고만 사용하고, 코인/코인지갑/IAP는 비활성.  
- 앱이 오프라인 전용이어도, **광고 노출 시점**만 온라인이라면(앱 실행 시 또는 특정 화면 진입 시 등) 수익화 가능.  
- 041(AdMob/AdRaven) 계획의 노출 정책·어댑터 구조를 그대로 활용하는 것이 좋다.
